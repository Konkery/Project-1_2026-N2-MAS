## 2. БИЗНЕС-КОНТЕКСТ ГК «ПЕРЕДОВЫЕ РЕШЕНИЯ»

### 2.1. Юридические лица и режимы налогообложения:
1.  **ООО «МАС» (Мобильные Автоматизированные Системы):** УСН «Доходы» (**6% без НДС**).
2.  **ООО «ГОРИЗОНТ»:** ОСНО (**22% НДС**).
3.  **ИП «Кукушкин И.Н.»:** УСН «Доходы» (**6% без НДС**).

### 2.2. Типология проектов и структура шифров:
*   **Классификация проектов:**
    *   `Контракт`: Коммерческий проект с внешним контрагентом или внутри группы, имеющий целевую норму прибыли.
    *   `Тендер`: Участие в конкурсной процедуре/гранте. Всегда разовый проект; в случае победы порождает новый контрактный проект с фиксацией связи с тендером.
    *   `Внутренний`: Некоммерческий проект для инфраструктурных, прикладных или организационных нужд группы компаний. **С 2026 года номер договора для внутренних проектов всегда строго равен `1`**.
*   **Шаблон шифра договора/проекта:** `[Номер]/[Год]-n[Заказ]-[Компания]`
    *   Пример: `5/2024-n0-мас` — рамочный договор;
    *   Пример: `5/2024-n1-мас` — заказ №1 по рамочному договору;
    *   Пример: `1/2026-n0-мас` — рамочный внутренний проект ООО «МАС» на 2026 год;
    *   **Пример текущего проекта: `1/2026-N2-МАС`** — внутренний проект ООО «МАС», заказ №2: разработка и внедрение BI-инструментов, ETL-процессора и прикладных спецификаций.

### 2.3. Взаимосвязь рамочных (`n0`) и прикладных (`n1`, `n2`...) проектов:
*   В рамочном проекте (`n0`) ведется консолидированная «Master Data» спецификация `work_spec` по всем заказам портфеля. В `n0` хранится полная коммерческая тайна (закупочные цены, поставщики, базовые наценки).
*   В проектах конкретных заказов (`n1`, `n2`...) разрабатываются и эксплуатируются локальные производные спецификации под задачи конкретного этапа или контрагента.

## 5. АРХИТЕКТУРА ДВИЖКА POWER QUERY (M) И ЯЗЫКА HORIZONBI

### 5.1. Библиотеки валидации и трансформаций:
1.  **`UtilsFunctionScalar` (актуальная версия: `rev.08 v04`):**
    Набор чистых скалярных функций валидации элементарных ячеек (возвращают `logical` -> `true`/`false`):
    *   Пустота и типы: `fvCheckNonEmpty_scalar`, `fvCheckInteger_scalar`, `fvCheckFloat_scalar`, `fvCheckBoolean_scalar`, `fvCheckDate_scalar`.
    *   Диапазоны: `fvCheckIntegerRange_scalar`, `fvCheckFloatRange_scalar`, `fvCheckDateRange_scalar`, `fvCheckTextLength_scalar`.
    *   Гос. реквизиты РФ: `fvCheckINN_LLC_scalar` (10 знаков с контрольной суммой), `fvCheckINN_Personal_scalar` (12 знаков с двумя контрольными суммами), `fvCheckKPP_scalar` (9 знаков), `fvCheckSNILS_scalar` (формат `XXX-XXX-XXX YY` с валидацией контрольного числа), `fvCheckPassportSeries_scalar`, `fvCheckPassportNumber_scalar`, `fvCheckPassportUnitCode_scalar`.
    *   Контакты: `fvCheckPhone_scalar` (стандарт `+7 XXX XXX-XX-XX`), `fvCheckEmail_scalar`.
2.  **`UtilsFunctionVector` (актуальная версия: `rev.08 v04`):**
    Векторные преобразования и проверки табличных массивов:
    *   Трансформации: `ftNormalizeDates`, `ftCapitalizeWords`, `ftToUpperCase`, `ftToLowerCase`, `ftTrimTextColumns`, `ftReorderColumnsStrict`, `ftRemoveColumnsStrict`, `ftCreateFullNameColumn`.
    *   Векторная валидация: `fvCheckID(_sourceTable as table, _columnName as text)` — строгий непрерывный инкремент первичного ключа от 1; ошибка в строке каскадно бракует все последующие строки.

### 5.2. ETL-процессор `ProcessingTable` (версия `rev.04 v01` / `rev.04 v02`):
*   **Сигнатура вызова:**
    ```m
    (
        _configJSONIndex as text,
        optional _pathExcelBook_1 as text,
        optional _pathExcelBook_2 as text,
        optional _pathExcelBook_3 as text,
        optional _pathExcelBook_4 as text
    ) as table => ...
    ```
*   **Механизм конфигурации:** Ищет JSON-документ в таблице `TabConfigJSON` текущей книги по ключу `IDconfig` в колонке `CONFIG_JSON`.
*   **Источники:** До 4 таблиц. Без указания путей — из текущей книги (`Excel.CurrentWorkbook(){[Name=TabName]}[Content]`), с путями — из внешних файлов (`Excel.Workbook(File.Contents(Path)){[Name=TabName]}[Data]`).

### 5.3. Язык инструкций `HorizonBI` (JSON DSL):
Каждый МакроБлок (`"1"`, `"2"`, ...) исполняет зарегистрированные команды в строго детерминированном системном порядке:
1.  `ColumnSetType` — принудительное назначение типов данных (`text`, `int`, `float`, `bool`).
2.  `ColumnFilterFreeData` — точная фильтрация строк по значению.
3.  `ColumnFilterUniqueData` — исключение дубликатов по заданному набору колонок (`Table.Distinct`).
4.  `RemoveRowOne` — удаление первой найденной строки по критерию поиска.
5.  `RemoveRowAll` — удаление всех строк по критерию.
6.  `InsertColumn` — добавление новых пустых колонок со значением `null`.
7.  `ColumnFillData` — заполнение всего столбца заданной константой (`Table.ReplaceValue`).
8.  `ModifyData` — точечная модификация полей найденной строки по ключевой колонке (поле `COMMENT` игнорируется).
9.  `RemoveXorColumn` — сохранение только указанного белого списка колонок (`Table.SelectColumns`).
10. `RemoveColumn` — безопасное удаление списка колонок.
11. `ClearColumn` — очистка значений колонок в `null`.
12. `RenameColumn` — переименование перечня столбцов.
13. `ReorderColumn` — упорядочивание колонок (неупомянутые помещаются в хвост).
14. **Операции слияния (Шаг 5):**
    *   `RunJOINdata` — вертикальное объединение строк таблиц с идентичной структурой (`Table.Combine`).
    *   `RunLeftJOINstructure` / `RunRightJOINstructure` — горизонтальное объединение структур по ключу `HASH COLLECTION` через `Table.NestedJoin` с последующим разворачиванием без дублирования ключа.
15. **Финальная валидация (Шаг 6):**
