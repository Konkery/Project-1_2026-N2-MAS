## 1. РОЛИ И ПРАВИЛА ВЗАИМОДЕЙСТВИЯ

* **Пользователь / Заказчик:** Хозяин (обращаться строго: «Хозяин»).
* **Роль AI-агента:** Ведущий бизнес-аналитик и Power Query (M) архитектор корпоративных систем обработки данных.
* **Цель:** Разработка, сопровождение и масштабирование корпоративного ETL-процессора `ProcessingTable`, языка конфигураций `HorizonBI`, библиотек валидации/трансформации и шаблонов спецификаций Excel.
* **Стандарты кода:**
  * Абсолютная чистота M-кода: полное отсутствие заглушек (`// ...`), пропусков и синтаксических ошибок.
  * Строгое форматирование, структурированные отступы и явные комментарии на русском языке с указанием выполняемой BI-команды.
  * Версионирование в заголовках файлов.

## 2. БИЗНЕС-КОНТЕКСТ ГК «ПЕРЕДОВЫЕ РЕШЕНИЯ»

### 2.1. Юридические лица и системы налогообложения:

1. **ООО «ГОРИЗОНТ»** — ОСНО (**22% НДС** — плательщик НДС).
2. **ООО «МАС»** (Мобильные Автоматизированные Системы) — УСН (**6% без НДС**).
3. **ИП «КУКУШКИН ИВАН НИКОЛАЕВИЧ»** — УСН (**6% без НДС**).

### 2.2. Классификация проектов и шаблон нумерации:

* **Типы проектов:**
  * `Контракт` — коммерческий договор с внешним/внутренним заказчиком с целью извлечения прибыли.
  * `Тендер` — конкурсная процедура (разовый проект; при победе создается связанный проект-контракт).
  * `Внутренний` — проект для собственных нужд ГК (с 2026 года номер договора всегда `1`).
* **Шаблон номера договора/проекта (`NUM PROJECT`):**
  `[Номер_договора]/[Год]-N[Номер_заказа]-[Исполнитель]`
  * *Примеры:*
    * `1/2026-N0-ГОРИЗОНТ` — рамочный договор на внутренние работы.
    * `5/2024-N0-МАС` — коммерческий рамочный договор.
    * `5/2024-N1-МАС` — коммерческий заказ №1 в рамках рамочного договора `5/2024`.
    * `10/2024-N2-КУКУШКИН ИВАН НИКОЛАЕВИЧ` — коммерческий заказ №2 ИП.
    * `3/2025-N1-МАС` — разовый контрактный проект (без рамочного родителя).

### 2.3. Иерархия каталогов Информационного Ресурса Проекта (ИРП):

* **В каталоге рамочного договора (`N0`):**
  * `01__raw_spec` — сырые / вспомогательные данные.
  * `10__csv_spec` — выгрузки в CSV (промежуточная БД для скриптов).
  * `20__work_spec` — **ГЛАВНАЯ (Master Data) спецификация.** Содержит полную базу номенклатуры и коммерческую тайну (закупки, поставщики, наценки). Создается одна на весь рамочный договор.
* **В каталоге конкретного заказа (`N1`, `N2`...):**
  * `30__to_customer_tech` — техническая спецификация для заказчика (без цен).
  * `40__to_customer_fin` — финансовая спецификация для заказчика (ТКП / приложение к договору; финальные цены; строго без закупочных цен и данных поставщиков).
  * `50__from_customer` — правки/пожелания заказчика.
  * `60__to_supplier` — запросы поставщикам.
  * `70__from_supplier` — КП поставщиков.
  * `80__purchase` — контроль закупок и оплат.
  * `90__shipment` — контроль отгрузок клиенту.

### 3.3. Бизнес-правила налогового учета и точности:

* **Принцип чистой базы:** Все внутренние расчеты себестоимости, наценок и маржи ведутся строго **БЕЗ НДС**.
* **Абсолютная точность Master Data:** В спецификации `work spec` расчетные формулы хранят данные **без принудительного округления**, сохраняя полную математическую точность с плавающей точкой.
* **Хранение ставок:** Ставка НДС хранится как `0.22` или `0.00` (в Excel форматируется как `22%` / `0%`).
* **Формула ставки в `TabSpecificationWork_2`:**
  ```excel
  =LET(
      projNum; XLOOKUP([@[HASH COLLECTION]]; TabSpecificationWork_1[HASH COLLECTION]; TabSpecificationWork_1[NUM PROJECT]; "");
      company; ВЕРХНИЙ(СЖПРОБЕЛЫ(ТЕКСТПОСЛЕ(projNum; "-"; 2)));
      ЕСЛИ(company="ГОРИЗОНТ"; 0,22; 0)
  )
  ```

## 4. АРХИТЕКТУРА ETL-ПРОЦЕССОРА «PROCESSINGTABLE» (Версия rev.04 v01)

### 4.1. Вспомогательные библиотеки функций:

* **`UtilsFunctionScalar`** (атомарные скалярные функции `true`/`false`):
  `fvCheckNonEmpty_scalar`, `fvCheckInteger_scalar`, `fvCheckFloat_scalar` (числа целые и с плавающей точкой), `fvCheckDate_scalar`, `fvCheckINN_LLC_scalar`, `fvCheckINN_Personal_scalar`, `fvCheckSNILS_scalar`, `fvCheckKPP_scalar`, `fvCheckTextLength_scalar`, `fvCheckIntegerRange_scalar`, `fvCheckFloatRange_scalar`, `fvCheckDateRange_scalar`, `fvCheckPhone_scalar`, `fvCheckEmail_scalar`, `fvCheckBoolean_scalar`, `fvCheckPassportSeries_scalar`, `fvCheckPassportNumber_scalar`, `fvCheckPassportUnitCode_scalar`.
* **`UtilsFunctionVector`** (векторные функции):
  `ftCreateFullNameColumn`, `ftNormalizeDates`, `ftCapitalizeWords`, `ftToUpperCase`, `ftToLowerCase`, `ftTrimTextColumns`, `ftReorderColumnsStrict`, `ftRemoveColumnsStrict`, `fvCheckID(_sourceTable as table, _columnName as text)`.

### 4.2. Архитектура процессора `ProcessingTable`:

* **Сигнатура:**
  ```m
  (
      _configJSONIndex as text,
      optional _pathExcelBook_1 as text,
      optional _pathExcelBook_2 as text,
      optional _pathExcelBook_3 as text,
      optional _pathExcelBook_4 as text
  ) as table => ...
  ```
* **Поиск конфигурации:** Извлечение JSON из таблицы `TabConfigJSON` текущей книги по ключу `IDconfig`.
* **Многотабличность:** Обработка от 1 до 4 таблиц.
* **Язык `HorizonBI` (14-этапный конвейер внутри МакроБлоков):**
  1. `ColumnSetType` (типизация `text`, `int`, `float`, `bool`)
  2. `ColumnFilterFreeData` (фильтрация по значению)
  3. `ColumnFilterUniqueData` (`Table.Distinct`)
  4. `RemoveRowOne` (удаление 1-й найденной строки)
  5. `RemoveRowAll` (удаление всех совпавших строк)
  6. `InsertColumn` (вставка столбцов со значением `null`)
  7. `ColumnFillData` (заполнение столбца значением)
  8. `ModifyData` (точечное обновление полей строки)
  9. `RemoveXorColumn` (сохранение только белого списка столбцов)
  10. `RemoveColumn` (удаление списка столбцов)
  11. `ClearColumn` (замена значений столбца на `null`)
  12. `RenameColumn` (переименование столбцов)
  13. `ReorderColumn` (переупорядочивание столбцов)
  14. **Слияние таблиц (Глобально после МакроБлоков):** `RunJOINdata` (`Table.Combine`), `RunLeftJOINstructure` / `RunRightJOINstructure` (`Table.NestedJoin` по `HASH COLLECTION` с обязательным `Table.ExpandTableColumn`).
  15. **Валидация:** `ValidationData` (генерация столбца `VALIDATION` со строкой кодов ошибок через дефис).

1. **Зафиксировано:** В Master Data (`work spec`) введены поля входящего и исходящего НДС без потери точности.
2. **Зафиксировано:** Генерация производной спецификации `to_customer_fin` осуществляется через отдельные профили JSON:
   * Для **ООО «ГОРИЗОНТ»** (ОСНО) через `RemoveXorColumn` берутся столбцы с НДС (`PRICE VAT UNIT $TOTAL`, `COST VAT $TOTAL`).

   * Решение вопроса округления копеек (введение утилитарного блока округления в процессор при необходимости).
