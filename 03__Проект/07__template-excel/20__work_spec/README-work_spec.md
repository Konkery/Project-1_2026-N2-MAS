## 1. ВВЕДЕНИЕ

### 1.1. Что такое спецификация `work spec`

**Спецификация `work spec`** — это Master Data документ в формате Microsoft Excel, содержащий:

- **Технические данные**: описание товаров/услуг, номенклатура, комплектация
- **Логистические данные**: количества, сроки поставки, статусы отгрузки
- **Финансовые данные**: цены закупки/продажи, НДС, скидки, маржа
- **Справочные данные**: поставщики, производители, единицы измерения

### 1.2. Роль в экосистеме HorizonBI

Спецификации `work spec`:

1. Являются **источником данных** для ETL-процессора `ProcessingTable`
2. Служат основой для генерации **производных спецификаций** (финансовые, технические, логистические)
3. Обеспечивают **единую точку истины** (Single Source of Truth) для всех проектов ГК
4. Интегрируются с системой валидации через язык конфигураций `HorizonBI`

### 1.3. Версионность

**Текущая версия шаблона**: rev.04 v02  
**Дата последнего обновления**: 08 сентября 2026 г.  
**Файл шаблона**: `Шаблон-спецификация work spec #2026.xlsx`

## 2. АРХИТЕКТУРА СПЕЦИФИКАЦИИ WORK SPEC

### 2.1. Структура файла Excel

Файл спецификации состоит из следующих листов:

| Лист                  | Тип             | Назначение                                                           |
| --------------------- | --------------- | -------------------------------------------------------------------- |
| `SpecificationWork_1` | Рабочий         | Основная таблица Master Data (техника, закупки, логистика)           |
| `SpecificationWork_2` | Рабочий         | Финансовая таблица (цены, НДС, скидки)                               |
| `SpecificationWork`   | Технологический | Объединенная таблица для Pivot (результат LEFT JOIN Work_1 + Work_2) |
| `Pivot`               | Аналитический   | Сводная таблица для анализа данных                                   |
| `TableSchema`         | Служебный       | **Схема данных и правила валидации**                                 |

| `HandbookProject`     | Справочник      | Список проектов (скрытый)                                            |
| `HandbookBrand`       | Справочник      | Справочник брендов/производителей (скрытый)                          |
| `HandbookSupplier`    | Справочник      | Справочник поставщиков (скрытый)                                     |
| `HandbookUnit`        | Справочник      | Единицы измерения (скрытый)                                          |

### 2.2. Связь между таблицами

```
TabSpecificationWork_1 (29 колонок)
         │
         │ [HASH COLLECTION] — ключ связи 1:1
         │
         ↓
TabSpecificationWork_2 (18 колонок)
         │
         │ LEFT JOIN
         │
         ↓
TabSpecificationWork (47 колонок) → Pivot → Аналитика
```

### 2.3. Ключевое поле связи

**`HASH COLLECTION`** — глобальный первичный ключ:

- Тип: text
- Формат: `{NUM PROJECT}-ver_{VER COLLECTION}-set_{IDset}-{isSHIPPED}`
- Пример: `1/2026-N2-МАС-ver_1-set_4.2-true`
- Уникальность: каждая строка имеет уникальный хэш
- Назначение: связь между технической (Work_1) и финансовой (Work_2) частями спецификации

## 3. ТАБЛИЦА TabTableSchema

### 3.1. Назначение и роль

**`TabTableSchema`** — служебная таблица, содержащая **полное описание структуры и правил валидации** для всех столбцов таблиц `TabSpecificationWork_1` и `TabSpecificationWork_2`.

#### Основные функции:

1. **Метаданные столбцов**: имя, тип данных, диапазон значений, обязательность заполнения
2. **Правила валидации**: уникальность, допустимость NULL, автоматическое заполнение
3. **Источники данных**: справочники, выпадающие списки
4. **Форматирование**: выравнивание, тип Excel-ячейки, перенос текста
5. **Документация**: комментарии и назначение каждого столбца

#### Применение:

- **Автоматическая генерация** JSON-конфигураций `ValidationData` для ETL-процессора
- **Документирование** структуры данных для разработчиков и пользователей
- **Контроль целостности**: проверка соответствия между фактической структурой таблиц и схемой

### 3.2. Расположение и структура

- **Диапазон**: A1:Q48 (17 колонок × 48 строк)
- **Записей**: 47 (29 для Work_1 + 18 для Work_2 + 1 заголовок)

- Обязательность: Да

  - `TabSpecificationWork_2` — финансовая таблица

---

#### Колонка 2: `NUM COLUMN`

**Назначение**: Порядковый номер столбца в целевой таблице

**Характеристики**:

- Тип данных: int (хранится как text)
- Обязательность: Да
- Диапазон:
  - Work_1: 1-29
  - Work_2: 1-18

**Особенности**:

- Нумерация начинается с 1 для каждой таблицы независимо
- Используется для сортировки и упорядочивания столбцов
- Критично для корректного маппинга при валидации

---

#### Колонка 3: `СOLUMNS NAME`

**Назначение**: Официальное английское имя столбца (как в смарт-таблице Excel)

**Характеристики**:

- Тип данных: text
- Обязательность: Да
- Уникальность: Да (в пределах одной таблицы)

**Примеры**:

- `IDnum`
- `NUM PROJECT`
- `VAT ADD PRICE $PURCHASE`
- `HASH COLLECTION`

**Применение**: Прямое обращение к столбцу в формулах Excel и JSON-конфигурациях

---

#### Колонка 4: `COLUMN NAME RUS`

**Назначение**: Русскоязычное название столбца для документации и пользовательского интерфейса

**Характеристики**:

- Тип данных: text
- Обязательность: Да

**Примеры**:

- `№ п/п`
- `НОМЕР ПРОЕКТА`
- `НДС $закуп`
- `Хэш комплекта`

**Применение**: Отображение в отчетах, производных спецификациях, сообщениях об ошибках

---

#### Колонка 5: `TYPE DATASET`

**Назначение**: Тип данных столбца для валидации

**Характеристики**:

- Тип данных: text (enum)
- Обязательность: Да
- Допустимые значения:
  - `int` — целое число
  - `float` — число с плавающей точкой (финансовые данные, коэффициенты)
  - `text` — текстовая строка

**Применение**: Определение функции валидации в `HorizonBI`:

- `int` → `fvCheckIntegerRange_scalar`
- `float` → `fvCheckFloatRange_scalar`
- `text` → `fvCheckTextLength_scalar`

---

#### Колонка 6: `RANGE VALUES`

**Назначение**: Допустимый диапазон значений для валидации

**Характеристики**:

- Тип данных: text (JSON-like format)
- Обязательность: Да
- Формат: `[min, max]`

**Примеры**:

- `[1, 300]` — для IDnum (целые числа от 1 до 300)
- `[0, 3000000]` — для VAT ADD PRICE $PURCHASE (float от 0 до 3 млн)
- `[3, 50]` — для NAME PRODUCT (текст длиной от 3 до 50 символов)

**Применение**: Параметры для функций валидации:

```m
fvCheckIntegerRange_scalar([1, 300])
fvCheckFloatRange_scalar([0, 3000000])
fvCheckTextLength_scalar([3, 50])
```

#### Колонка 7: `UNIQUE FLAG`

**Назначение**: Флаг уникальности значений в столбце

**Характеристики**:

- Тип данных: bool (хранится как text)
- Обязательность: Да
- Значения:
  - `true` — значения должны быть уникальными
  - `false` — допускаются дубликаты

**Примеры уникальных столбцов**:

- `IDnum` — порядковый номер записи
- `HASH COLLECTION` — глобальный ключ
- `ARTICLE INTERNAL` — внутренний артикул

**Применение**: Генерация проверки `ColumnFilterUniqueData` в JSON-конфигурации

#### Колонка 8: `NULL VALUE`

**Назначение**: Допустимость пустых (NULL) значений

**Характеристики**:

- Тип данных: bool (хранится как text)
- Обязательность: Да
- Значения:
  - `true` — столбец может быть пустым
  - `false` — обязательное заполнение

**Применение**: Генерация проверки `fvCheckNonEmpty` в блоке `ValidationData`

**Примеры**:

- `NUM PROJECT` → `false` (обязательно)
- `COMMENT WORK` → `true` (опционально)

#### Колонка 9: `isAUTOMATIC`

**Назначение**: Флаг автоматического вычисления значения

**Характеристики**:

- Тип данных: bool (хранится как text)
- Обязательность: Да
- Значения:
  - `true` — значение вычисляется автоматически (формула Excel или Power Query)
  - `false` — значение заполняется вручную

**Примеры автоматических столбцов**:

- `NUM ORDER` — автоматически вычисляется при выборе NUM PROJECT
- `QUANTITY TOTAL` — автовычисление: `QUANTITY SET × QUANTITY SHIPPED SET`
- `VAT RATE CONTRACTOR $TOTAL` — автоопределение по юрлицу через XLOOKUP
- `COST $TOTAL` — автовычисление: `QUANTITY TOTAL × PRICE UNIT $TOTAL`

**Применение**:

- Определение полей, которые **нельзя изменять** в производных спецификациях
- Пропуск валидации для автовычисляемых полей (они проверяются косвенно через исходные данные)

---

#### Колонка 10: `MODIFY FLAG`

**Назначение**: Флаг возможности ручной модификации автовычисляемого значения

**Характеристики**:

- Тип данных: bool (хранится как text)
- Обязательность: Да
- Значения:
  - `true` — автовычисляемое значение можно переопределить вручную
  - `false` — значение строго автоматическое, ручное изменение запрещено

**Комбинации с `isAUTOMATIC`**:

| isAUTOMATIC | MODIFY FLAG | Поведение                                     |
| ----------- | ----------- | --------------------------------------------- |
| `false`     | `false`     | Ручной ввод, без ограничений                  |
| `true`      | `false`     | Строго автоматическое, изменение запрещено    |
| `true`      | `true`      | Автовычисление с возможностью переопределения |

**Примеры модифицируемых автополей**:

- `PRICE UNIT $TOTAL` — автовычисляется, но можно скорректировать вручную для индивидуальных скидок
- `VAT ADD PRICE UNIT $TOTAL` — автовычисляется, но можно переопределить при особых условиях

**Применение**: Определение полей для **условной валидации** в производных спецификациях

## 9. ГЕНЕРАЦИЯ JSON-КОНФИГУРАЦИЙ ДЛЯ ВАЛИДАЦИИ

### 9.1. Алгоритм преобразования TabTableSchema в ValidationData

**Входные данные**: Запись из `TabTableSchema` (17 полей)

**Выходные данные**: Блок `ValidationData` для JSON-конфигурации `HorizonBI`

### 9.2. Маппинг полей

| Поле TabTableSchema | Применение в ValidationData | Функция валидации                                          |
| ------------------- | --------------------------- | ---------------------------------------------------------- |
| `СOLUMNS NAME`      | Имя столбца для валидации   | Ключ в блоке `{ "ИмяСтолбца": {...} }`                     |

|                     |                             | `float` → `fvCheckFloatRange_scalar`                       |

| `UNIQUE FLAG`       | Проверка уникальности       | `true` → использовать `ColumnFilterUniqueData` в конвейере |

### 9.4. Псевдокод алгоритма генерации

```python
def generate_validation_data(schema_record):
    """
    Генерация блока ValidationData из записи TabTableSchema
    """
    column_name = schema_record["СOLUMNS NAME"]
    data_type = schema_record["TYPE DATASET"]
    range_values = parse_range(schema_record["RANGE VALUES"])  # [min, max]
    null_allowed = schema_record["NULL VALUE"] == "true"
    unique = schema_record["UNIQUE FLAG"] == "true"

    validation_rules = {}

    # Проверка на пустоту
    if not null_allowed:
        validation_rules["fvCheckNonEmpty"] = []

    # Проверка диапазона
    if data_type == "int":
        validation_rules["fvCheckIntegerRange_scalar"] = range_values
    elif data_type == "float":
        validation_rules["fvCheckFloatRange_scalar"] = range_values
    elif data_type == "text":
        validation_rules["fvCheckTextLength_scalar"] = range_values

    # Формирование блока
    validation_block = {column_name: validation_rules}

    return validation_block, unique


def generate_full_config(table_name):
    """
    Генерация полной JSON-конфигурации для таблицы
    """
    records = get_schema_records(table_name)  # Все записи TabTableSchema для таблицы

    validation_data = []
    unique_columns = []

    for record in records:
        block, is_unique = generate_validation_data(record)
        validation_data.append(block)

        if is_unique:
            unique_columns.append(record["СOLUMNS NAME"])

    config = {
        "ColumnFilterUniqueData": unique_columns,
        "ValidationData": validation_data
    }

    return config
```
