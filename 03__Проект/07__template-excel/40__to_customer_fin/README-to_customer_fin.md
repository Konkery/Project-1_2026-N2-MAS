# ДОКУМЕНТАЦИЯ: ФИНАНСОВАЯ СПЕЦИФИКАЦИЯ TO_CUSTOMER_FIN (тип 40)

---

## 1. НАЗНАЧЕНИЕ И БИЗНЕС-РОЛЬ

Спецификация типа `to_customer_fin` является ключевым коммерческим документом в проектном цикле ГК «Передовые решения». 

Несмотря на то, что инструментально (в среде разработки) она формируется в MS Excel и классифицируется как «техническая», по своей бизнес-роли это **внешний коммерческий документ**. Именно эта спецификация, после согласования, конвертируется в формат PDF/DOCX и становится юридически значимым приложением к Договору с заказчиком или финальным Технико-Коммерческим Предложением (ТКП).

### 1.1. Главные принципы
1. **Изоляция коммерческой тайны:** Из датасета жестко удаляются все внутренние финансовые показатели (закупочные цены, плановая себестоимость, коэффициенты торговой наценки), а также данные о реальных поставщиках и внутренние служебные комментарии.
2. **Точность и баланс:** В документе применяются строгие правила банковского округления, гарантирующие идеальный баланс строки: `Цена × Количество = Стоимость` вплоть до копейки, что критично для загрузки в 1С и бухгалтерского учета заказчика.

## 2. КЛАССИФИКАЦИЯ КОНФИГУРАЦИЙ (JSON DSL)

В связи с наличием в холдинге компаний с разными режимами налогообложения (ОСНО 22% НДС и УСН 0%), а также разными типами контрактов (только услуги / поставка оборудования), разработано **4 типа конфигураций**.

> Все конфигурации генерируются ETL-процессором `ProcessingTable` на базе единого источника данных — консолидированной смарт-таблицы `TabSpecificationWork`.

### Тип 1. УСН (0%) / Поставка + Услуги
Предназначен для ООО «МАС» и ИП. **Не содержит НДС-колонок; в конфигурации полностью отсутствуют проверки и команды, связанные с НДС** (бизнес-решение холдинга: понятие НДС не свойственно документам компаний на УСН). Конвейер 6 блоков, без `FinancialRound`. Статус: разработана, ожидает тестирования (тест-шифр `27/2025-N1-МАС`).

### Тип 2. УСН (0%) / Только Услуги
Аналогичен Типу 1 по составу и структуре; отличается заголовком длительности («ДЛИТЕЛЬНОСТЬ РЕАЛИЗАЦИИ, КАЛ. ДНЕЙ»). Статус: разработана, ожидает тестирования (тест-шифр `27/2025-N1-МАС`).

### Тип 3. ОСНО (22%) / Поставка + Услуги
Предназначен для ООО «ГОРИЗОНТ». Явно выделяет сумму НДС и итоговые значения. Отличается от Типа 4 заголовком длительности («ДЛИТЕЛЬНОСТЬ ПОСТАВКИ, КАЛ. ДНЕЙ»). Статус: разработана, ожидает тестирования (тест-шифр `8/2026-N2-ГОРИЗОНТ`).

### Тип 4. ОСНО (22%) / Только Услуги
Конфигурация для контрактов ООО «ГОРИЗОНТ» без отгрузки материальных ТМЦ. Статус: **разработана и протестирована** (тест-шифр `8/2026-N1-ГОРИЗОНТ`) — эталонная конфигурация семейства.

## 3. ЭТАЛОННЫЕ СТРУКТУРЫ КОНФИГУРАЦИЙ

### 3.1. Общий конвейер (типы 3 и 4, ОСНО)

Конвейер из **7 МакроБлоков** (нумерация секций обязательна, порядок исполнения команд внутри блока задается фиксированным конвейером ядра):

| Блок | Команды | Назначение |
| :--: | :------ | :---------- |
| 1 | `ValidationData` + `StrictBlock` | Пред-валидация мастера (41 поле) до любых трансформаций |
| 2 | `ColumnFilterFreeData`, `RemoveRowAll` | Изоляция заказа по `NUM PROJECT`; отсечение неотгруженных позиций (`isSHIPPED = false`) |
| 3 | `FilterSpecMaxVer` | Детерминированный отбор старших версий позиций |
| 4 | `ModifyData` | **Обязательный блок скрытой модификации** (протокол `MODIFY FLAG` / `isPROCESSING`, см. README work spec §8); штатно пуст `[]` |
| 5 | `RemoveXorColumn`, `FinancialRound` | Предварительная изоляция (keep 11 полей для округления); банковское округление и балансировка `Цена × Кол-во = Стоимость` |
| 6 | `RemoveXorColumn`, `RenameColumn` | Финальная клиентская сетка (8 полей); локализация заголовков |
| 7 | `ColumnSetType` | Фиксация типов для корректного отображения в Excel |

### 3.2. Состав итоговых столбцов (Тип 4, эталон)

| Исходный столбец (work_spec) | Целевой столбец (to_customer_fin) | Тип данных | Описание / Источник |
| :--- | :--- | :--- | :--- |
| `NUM FULL SET` | **№** | `text` | Полный иерархический номер позиции |
| `NAME PRODUCT` | **НАИМЕНОВАНИЕ** | `text` | Наименование услуги |
| `UNITS` | **ЕД ИЗМ.** | `text` | Единица измерения |
| `QUANTITY TOTAL` | **КОЛ-ВО** | `int` | Итоговое количество |
| `PRICE UNIT $TOTAL` | **ЦЕНА БЕЗ НДС, руб** | `float` | Округленная цена за единицу |
| `COST $TOTAL` | **СТОИМОСТЬ БЕЗ НДС, руб** | `float` | Округленная стоимость |
| `COST ADD VAT $TOTAL` | **НДС, руб** | `float` | Округленная сумма налога |
| `DURATION SALE $TOTAL` | **ДЛИТЕЛЬНОСТЬ РЕАЛИЗАЦИИ, КАЛ. ДНЕЙ** | `int` | Срок оказания услуги |

### 3.3. Состав итоговых столбцов (Тип 3)

Идентичен Типу 4, исключение — строка 8: `DURATION SALE $TOTAL` → **ДЛИТЕЛЬНОСТЬ ПОСТАВКИ, КАЛ. ДНЕЙ**. Тест-шифр блока 2: `8/2026-N2-ГОРИЗОНТ`.

### 3.4. Состав итоговых столбцов (Тип 2, УСН / услуги)

| Исходный столбец (work_spec) | Целевой столбец (to_customer_fin) | Тип данных |
| :--- | :--- | :--- |
| `NUM FULL SET` | **№** | `text` |
| `NAME PRODUCT` | **НАИМЕНОВАНИЕ** | `text` |
| `UNITS` | **ЕД ИЗМ.** | `text` |
| `QUANTITY TOTAL` | **КОЛ-ВО** | `int` |
| `PRICE UNIT $TOTAL` | **ЦЕНА, руб** | `float` |
| `COST $TOTAL` | **СТОИМОСТЬ, руб** | `float` |
| `DURATION SALE $TOTAL` | **ДЛИТЕЛЬНОСТЬ РЕАЛИЗАЦИИ, КАЛ. ДНЕЙ** | `int` |

### 3.5. Состав итоговых столбцов (Тип 1, УСН / поставка + услуги)

Идентичен Типу 2, исключение — строка 7: **ДЛИТЕЛЬНОСТЬ ПОСТАВКИ, КАЛ. ДНЕЙ**.

### 3.6. Особенности конвейера УСН (типы 1 и 2)

* Конвейер из **6 блоков**: отсутствует блок `FinancialRound` (бизнес-решение: в DSL УСН нет команд расчета НДС и связанного с ним финансового округления; финансовые колонки переносятся из мастера со значениями, рассчитанными формулами).
* Пред-валидация блока 1 содержит **34 поля**: все 7 НДС-связанных полей мастера (`VAT ADD PRICE $PURCHASE`, `COST PRICE VAT $PURCHASE`, `VAT RATE CONTRACTOR $TOTAL`, `VAT ADD PRICE UNIT $TOTAL`, `PRICE VAT UNIT $TOTAL`, `COST ADD VAT $TOTAL`, `COST VAT $TOTAL`) исключены из проверок.
* Токены `VAT` и `НДС` полностью отсутствуют в файлах конфигураций УСН.

### 3.7. Именная конвенция и `IDconfig`

* Файлы DSL-конфигураций: `ProcessingDSL - to customer fin - type{1..4}.json` в каталоге `03__Проект/05__pq-script/01__general/03__etl-processing/ШАБЛОНЫ-JSON DSL/`.
* `IDconfig` в таблице `TabConfigJSON` книги = базовое имя файла без расширения (например, `ProcessingDSL - to customer fin - type3`).
