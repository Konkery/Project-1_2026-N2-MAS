## Документация. ETL-процессор `ProcessingTable`

#### Текущая ревизия и версия:
`rev.04 v01`

#### Полное описание назначения и возможностей процессора:

`ProcessingTable` — это универсальный ETL-процессор, реализованный как функция-запрос в Power Query. Его основное назначение — выполнять сложную, многоэтапную обработку и валидацию данных из таблиц Excel, руководствуясь декларативными инструкциями на разработанном нами языке `HorizonBI`. Эти инструкции передаются в виде JSON-конфигуратора.

**Ключевые возможности:**

1.  **Управление через JSON:** Вся логика обработки описывается в JSON-конфигураторе, что отделяет правила обработки от кода и делает систему гибкой.
2.  **Централизованная конфигурация:** Процессор находит нужный JSON-конфигуратор в специальной таблице `TabConfigJSON` по уникальному текстовому ID, передаваемому в качестве аргумента.
3.  **Работа с несколькими источниками:** Процессор способен одновременно обрабатывать **до четырех таблиц**. Источники данных могут находиться как в текущей книге Excel, так и во внешних файлах, пути к которым указываются в аргументах.
4.  **Многошаговая обработка (МакроБлоки):** JSON-конфигурация поддерживает систему "МакроБлоков" (секций с числовыми именами: "1", "2" и т.д.). Процессор выполняет эти блоки последовательно, в порядке возрастания их номеров.
5.  **Богатый набор операций:** Внутри каждого МакроБлока процессор выполняет широкий спектр BI-операций, от фильтрации и модификации данных до слияния структур и финальной валидации.
6.  **Операции слияния:** Процессор поддерживает три вида слияния для многотабличных конфигураций: `RunLeftJOINstructure`, `RunRightJOINstructure` и `RunJOINdata`.
7.  **Финальная валидация:** В качестве опционального последнего шага процессор может выполнить валидацию данных и добавить в итоговую таблицу столбец `VALIDATION`.
8.  **Опора на библиотеки функций:** Процессор использует две внешние библиотеки (`UtilsFunctionVector` и `UtilsFunctionScalar`) для выполнения специфических задач валидации.

#### Список и порядок выполнения команд языка HorizonBI

Процессор выполняет команды **внутри каждого МакроБлока** в следующем строгом порядке:

1.  **`ColumnSetType`**: Устанавливает типы данных для указанных столбцов.
2.  **`ColumnFilterFreeData`**: Фильтрует строки, оставляя те, что равны заданному значению.
3.  **`ColumnFilterUniqueData`**: Фильтрует строки, оставляя только уникальные значения в указанном столбце.
4.  **`RemoveRowOne`**: Удаляет **первую** найденную строку, удовлетворяющую критерию.
5.  **`RemoveRowAll`**: Удаляет **все** строки, удовлетворяющие критерию.
6.  **`InsertColumn`**: Вставляет новые, пустые столбцы.
7.  **`ColumnFillData`**: Заполняет весь столбец одним заданным значением.
8.  **`ModifyData`**: Изменяет значения в конкретных ячейках найденных строк.
9.  **`RemoveXorColumn`**: **Оставляет** только указанные столбцы, удаляя все остальные.
10. **`RemoveColumn`**: **Удаляет** указанные столбцы.
11. **`ClearColumn`**: Очищает все значения в указанных столбцах (заменяет на `null`).
12. **`RenameColumn`**: Переименовывает столбцы.
13. **`ReorderColumn`**: Переупорядочивает столбцы.
14. **`RunLeftJOINstructure` / `RunRightJOINstructure` / `RunJOINdata`**: Выполняет операцию слияния (только для многотабличных конфигураций).
15. **`ValidationData`**: Запускает валидацию и добавляет итоговый столбец `VALIDATION`.

#### Примеры сигнатур команд в JSON

1.  **`ColumnSetType`**
    ```json
    "ColumnSetType": [
        { "ИмяСтолбца1": "int" },
        { "ИмяСтолбца2": "text" }
    ]
    ```

2.  **`ColumnFilterFreeData`**
    ```json
    "ColumnFilterFreeData": [
        { "ИмяСтолбца": "ЗначениеДляФильтра" }
    ]
    ```

3.  **`ColumnFilterUniqueData`**
    ```json
    "ColumnFilterUniqueData": [
        "ИмяСтолбца1",
        "ИмяСтолбца2"
    ]
    ```

4.  **`RemoveRowOne`**
    ```json
    "RemoveRowOne": [
        { "rule_1": { "IndexSearchColumn": "ИмяСтолбца", "IndexSearchRow": "ЗначениеДляПоиска" } }
    ]
    ```

5.  **`RemoveRowAll`**
    ```json
    "RemoveRowAll": [
        { "rule_1": { "IndexSearchColumn": "ИмяСтолбца", "IndexSearchRow": "ЗначениеДляПоиска" } }
    ]
    ```

6.  **`InsertColumn`**
    ```json
    "InsertColumn": [
        "ИмяНовогоСтолбца1",
        "ИмяНовогоСтолбца2"
    ]
    ```

7.  **`ColumnFillData`**
    ```json
    "ColumnFillData": [
        { "ИмяСтолбца": "НовоеЗначениеДляВсехЯчеек" }
    ]
    ```

8.  **`ModifyData`**
    ```json
    "ModifyData": [
        { 
            "data_1": { 
                "IndexSearchColumn": "КлючевойСтолбец", 
                "IndexSearchRow": "ЗначениеДляПоиска", 
                "NewData": { "СтолбецДляИзменения": "НовоеЗначение" } 
            } 
        }
    ]
    ```

9.  **`RemoveXorColumn`**
    ```json
    "RemoveXorColumn": [
        "СтолбецДляСохранения1",
        "СтолбецДляСохранения2"
    ]
    ```

10. **`RemoveColumn`**
    ```json
    "RemoveColumn": [
        "СтолбецДляУдаления1",
        "СтолбецДляУдаления2"
    ]
    ```

11. **`ClearColumn`**
    ```json
    "ClearColumn": [
        "СтолбецДляОчистки1",
        "СтолбецДляОчистки2"
    ]
    ```

12. **`RenameColumn`**
    ```json
    "RenameColumn": [
        { "СтароеИмя": "НовоеИмя" }
    ]
    ```

13. **`ReorderColumn`**
    ```json
    "ReorderColumn": [
        "ПервыйСтолбец",
        "ВторойСтолбец"
    ]
    ```

14. **`RunLeftJOINstructure` / `RunRightJOINstructure` / `RunJOINdata`**
    ```json
    "RunLeftJOINstructure": []
    ```

15. **`ValidationData`**
    ```json
    "ValidationData": [
        { "ИмяСтолбца": { "fvCheckNonEmpty": [], "fvCheckTextLength": [5, 100] } }
    ]
    `
