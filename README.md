# ПРОЕКТ 1/2026-N2-МАС: ЭКОСИСТЕМА HORIZONBI

**Универсальный инструментарий BI для управления проектами и заказами**  
**Группа компаний «ПЕРЕДОВЫЕ РЕШЕНИЯ»**

---

## ВВЕДЕНИЕ

**Проект 1/2026-N2-МАС** — это комплексная разработка BI-инструментов для автоматизации внутренних бизнес-процессов Группы компаний «ПЕРЕДОВЫЕ РЕШЕНИЯ». В центре экосистемы находится **ETL-процессор ProcessingTable** и система **спецификаций данных**, обеспечивающих единую точку истины (Single Source of Truth) для всех проектов ГК.

Проект зарегистрирован как **Заказ №2** в рамках внутреннего рамочного проекта **1/2026-N0-МАС** в структуре ООО «МАС».

### История и преемственность

Проект является прямым наследником **PowerQueryScript** — ранней разработки, которая была принудительно прекращена из-за несоответствия регламенту оформления. Все наработки PowerQueryScript полностью перешли в текущий проект, обеспечив непрерывность развития.

## ОБЗОР ПРОЕКТА

### Ключевые компоненты экосистемы HorizonBI

1. **Система спецификаций данных** — централизованное хранилище Master Data по всем проектам с автоматической генерацией производных документов
2. **ETL-процессор ProcessingTable** — универсальный движок обработки табличных данных с языком конфигураций HorizonBI (JSON DSL)
3. **Библиотеки валидации** — набор функций Power Query (M) для проверки целостности данных
4. **Справочники** — нормализованные справочные данные (проекты, поставщики, бренды, единицы измерения)

### Бизнес-контекст ГК «ПЕРЕДОВЫЕ РЕШЕНИЯ»

Группа компаний включает несколько юридических лиц с разными налоговыми режимами:

| Юрлицо | Налоговый режим | Ставка НДС | Применение |
|--------|-----------------|------------|------------|
| **ООО «ГОРИЗОНТ»** | ОСНО | 22% | Проекты с НДС для крупных заказчиков |
| **ООО «МАС»** | УСН | 0% | Проекты без НДС |
| **ИП Кукушкин И.Н.** | УСН | 0% | Малые проекты и услуги |

Экосистема HorizonBI автоматически определяет налоговый режим по номеру проекта и корректно рассчитывает все финансовые показатели с учетом НДС.

### Принципы архитектуры

- **Принцип чистой базы**: все расчеты себестоимости и маржи ведутся БЕЗ НДС, НДС добавляется отдельными колонками
- **Абсолютная точность**: Master Data не содержит принудительного округления, точность сохраняется до копеек
- **Единая точка истины**: все производные документы генерируются из одного источника — спецификации `work spec`
- **Автоматизация**: 90% расчетов выполняются автоматически, человек контролирует только ключевые параметры

## СИСТЕМА СПЕЦИФИКАЦИЙ

### 1. Главная спецификация: work spec (тип 20)

**Назначение**: Master Data документ — единый источник данных для всех проектов и заказов ГК.

**Архитектура**:
- Две связанные смарт-таблицы Excel (связь 1:1 по глобальному ключу `HASH COLLECTION`)
- **TabSpecificationWork_1** (29 колонок): техника, закупки, логистика, номенклатура
- **TabSpecificationWork_2** (18 колонок): экономика, цены реализации, НДС, скидки
- **TabTableSchema** (47 записей): метаданные и правила валидации для всех колонок

**Ключевые возможности**:
- ✅ Поддержка входящего и исходящего НДС (rev.04 v02)
- ✅ Автоматическое определение ставки НДС по юрлицу (0% или 22%)
- ✅ Генерация производных спецификаций через ETL-процессор
- ✅ Валидация данных на основе TabTableSchema
- ✅ Справочники для нормализации данных (проекты, поставщики, бренды)

**Структура данных**:

**TabSpecificationWork_1** включает:
- Идентификация: номер проекта, версия коллекции, комплектация
- Номенклатура: наименование, артикулы, бренд, поставщик
- Количества: в комплекте, в отгрузке, итого
- Финансы закупки: цена без НДС, входящий НДС, себестоимость
- Дополнительно: ссылки на товары, изображения, комментарии

**TabSpecificationWork_2** включает:
- Ценообразование: наценка, базовая цена, скидки
- НДС-блок (5 колонок):
  - Ставка НДС исполнителя (автоопределение)
  - Исходящий НДС на единицу и на стоимость
  - Цены и стоимость С НДС
- Логистика: сроки поставки, статусы наличия и постобработки
- Комментарий для заказчика

**→ Детальная документация**: [README-work_spec.md](./README-work_spec.md)

**30__to_customer_tech** — Техническая спецификация

**Назначение**: Документ для инженеров заказчика с техническими характеристиками оборудования.

**Содержит**:
- Артикулы и наименования товаров
- Технические характеристики и описания

- Количества и единицы измерения
- Сроки поставки
- Комментарии для заказчика

**Не содержит**: цены, поставщики, коммерческая тайна, внутренние комментарии

**Формат**: Excel (чистый, без формул)

**→ Документация**: [README-to_customer_tech.md](./README-to_customer_tech.md)

**40__to_customer_fin** — Финансовая спецификация (ТКП)

**Назначение**: Коммерческое предложение для руководства заказчика с ценами и сроками.

**Содержит**:
- Наименования и краткие описания

- Сроки поставки
- Итоговые суммы

**Не содержит**: артикулы поставщиков, себестоимость, наценка, внутренние данные

**Особенности**:
- Для ООО «ГОРИЗОНТ» (ОСНО): отображаются колонки `PRICE VAT UNIT $TOTAL` и `COST VAT $TOTAL` (с НДС)
- Для ООО «МАС» и ИП (УСН): отображаются колонки `PRICE UNIT $TOTAL` и `COST $TOTAL` (без НДС)

**Формат**: Excel (защищенный от редактирования) + PDF

## ETL-ПРОЦЕССОР PROCESSINGTABLE

### Назначение

**ProcessingTable** — универсальный движок обработки табличных данных на языке Power Query (M). Процессор принимает на вход Excel-таблицы и JSON-конфигурацию, выполняет трансформации, валидацию и генерирует результирующую таблицу.

### Архитектура

**Входные данные**:
- 1-4 таблицы Excel (source tables)
- JSON-конфигурация HorizonBI (язык DSL для описания обработки)

**Выходные данные**:
- Обработанная таблица (валидированная, трансформированная, очищенная)

**Этапы обработки** (14-этапный конвейер):
1. `ColumnSetType` — типизация колонок (text, int, float, bool)
2. `ColumnFilterFreeData` — фильтрация по значению
3. `ColumnFilterUniqueData` — удаление дубликатов
4. `RemoveRowOne` — удаление первой найденной строки
5. `RemoveRowRange` — удаление диапазона строк
6. `RemoveRowNull` — удаление пустых строк
7. `JoinTable` — слияние таблиц (LEFT/RIGHT/INNER/FULL JOIN)
8. `RenameColumn` — переименование колонок
9. `RemoveXorColumn` — удаление/сохранение колонок
10. `ReorderColumn` — переупорядочивание колонок
11. `ReorderColumnStrict` — строгое переупорядочивание (с ошибкой при несоответствии)
12. `TransformData` — векторные трансформации (капитализация, trim, и т.д.)
13. `ValidationData` — валидация данных через библиотеки UtilsFunction
14. Финальная сборка результата

### Язык конфигураций HorizonBI

**Формат**: JSON DSL

**Пример конфигурации** (генерация 40__to_customer_fin для ОСНО):

```json
{
  "SourceTableName": "TabSpecificationWork",
  "RemoveXorColumn": [
    "SUPPLIER", "ARTICLE SUPPLIER", "ARTICLE INTERNAL",
    "PRICE UNIT $PURCHASE", "COST PRICE $PURCHASE",
    "COEFFICIENT MARKUP", "DISCOUNT PERCENT"
  ],
  "RenameColumn": [
    { "PRICE VAT UNIT $TOTAL": "Цена за ед. с НДС, руб." },
    { "COST VAT $TOTAL": "Стоимость с НДС, руб." }
  ],
  "ReorderColumn": [
    "NUM PROJECT", "NAME PRODUCT", "QUANTITY TOTAL",
    "Цена за ед. с НДС, руб.", "Стоимость с НДС, руб."
  ],
  "ValidationData": [
    {
      "NUM PROJECT": {
        "fvCheckNonEmpty": [],
        "fvCheckTextLength_scalar": [13, 25]
      }
    }
  ]
}
```

## БИБЛИОТЕКИ ФУНКЦИЙ POWER QUERY (M)

### UtilsFunctionScalar — Скалярные функции валидации

**Назначение**: Атомарные функции для проверки одиночных значений (возвращают `true`/`false`).

**Основные функции**:
- `fvCheckIntegerRange_scalar([min, max])` — проверка целого числа в диапазоне
- `fvCheckFloatRange_scalar([min, max])` — проверка числа с плавающей точкой
- `fvCheckTextLength_scalar([min, max])` — проверка длины текста
- `fvCheckINN_LLC_scalar()` — проверка ИНН юрлица (10 цифр)
- `fvCheckINN_Personal_scalar()` — проверка ИНН физлица (12 цифр)
- `fvCheckSNILS_scalar()` — проверка СНИЛС
- `fvCheckEmail_scalar()` — проверка email
- `fvCheckPhone_scalar()` — проверка телефона РФ

**Применение**: Используются в блоке `ValidationData` конфигураций HorizonBI.

### UtilsFunctionVector — Векторные функции трансформации

**Назначение**: Массовые преобразования колонок таблицы.

**Основные функции**:
- `ftCapitalizeWords(table, columns)` — капитализация слов
- `ftToUpperCase(table, columns)` — перевод в верхний регистр
- `ftToLowerCase(table, columns)` — перевод в нижний регистр
- `ftTrimTextColumns(table, columns)` — удаление пробелов
- `ftReorderColumnsStrict(table, order)` — строгое переупорядочивание
- `ftRemoveColumnsStrict(table, columns)` — строгое удаление колонок
- `fvCheckID(table, column)` — проверка уникальности ID

**Применение**: Используются в блоке `TransformData` конфигураций HorizonBI.

### Справочники (Handbooks)

**Назначение**: Централизованное хранение нормализованных справочных данных.

**Основные справочники**:
- `TabProjectList` — список проектов ГК (номер, юрлицо, генподрядчик, главный инженер)
- `TableVendorAndBrand` — справочник брендов и производителей
- `TabSupplier` — справочник поставщиков (название, контакты)
- `TabUnits` — единицы измерения (шт, кг, м, комплект)
- `TabTCPSupplier` — справочник ТКП поставщиков

**Применение**: Выпадающие списки в Excel, валидация данных, нормализация.

## КАК НАЧАТЬ РАБОТУ

### Шаг 1: Создание новой спецификации проекта

1. **Скопировать шаблон**:
   ```
   03__Проект/07__template-excel/20__work_spec/
   Шаблон-спецификация work spec #2026.xlsx
   ```

2. **Переименовать** в формат:
   ```
   {NUM PROJECT}_work_spec.xlsx
   Пример: 1-2026-N2-МАС_work_spec.xlsx
   ```

3. **Разместить** в структуре ИРП:
   ```
   05__Данные/{NUM PROJECT}/20__work_spec/
   ```

### Шаг 2: Заполнение Master Data

1. **Открыть лист `SpecificationWork_1`**:
   - Выбрать `NUM PROJECT` из справочника (автоматически заполнится `NUM ORDER`)
   - Заполнить описание комплектов (`DESCRIPTION SET`, `IDset`)
   - Ввести номенклатуру (`NAME PRODUCT`, `BRAND`)
   - Указать количества (`QUANTITY SET`, `QUANTITY SHIPPED SET`)
   - Ввести цены закупки (`PRICE UNIT $PURCHASE`, `VAT ADD PRICE $PURCHASE`)

2. **Открыть лист `SpecificationWork_2`**:
   - Система автоматически подтянет ключевые поля из Work_1 (технологические колонки A-E)
   - Задать коэффициент наценки (`COEFFICIENT MARKUP`)
   - При необходимости указать скидки (`DISCOUNT PERCENT`)
   - Система автоматически рассчитает:
     - Ставку НДС по юрлицу (`VAT RATE CONTRACTOR $TOTAL`)
     - Цены с НДС (`PRICE VAT UNIT $TOTAL`, `COST VAT $TOTAL`)

3. **Обновить `SpecificationWork`** (объединенную таблицу):
   - Перейти на вкладку `Данные` → `Обновить все`
   - Power Query выполнит LEFT JOIN между Work_1 и Work_2

### Шаг 3: Генерация производных спецификаций

1. **Открыть Power Query** (Excel → Данные → Запросы и подключения)

2. **Вызвать ProcessingTable**:
   ```m
   ProcessingTable(
       "config_40_to_customer_fin_OSNO",  // ID конфигурации из TabConfigJSON
       "путь/к/работа_spec.xlsx"          // Путь к файлу work spec
   )
   ```

3. **Загрузить результат** в новую книгу Excel:
   - Главная → Закрыть и загрузить → Загрузить в...
   - Выбрать "Таблица" и "Новый лист"

4. **Сохранить** производную спецификацию:
   ```
   06__Выход/{NUM PROJECT}/40__to_customer_fin/
   {NUM PROJECT}_to_customer_fin_v01.xlsx
   ```

### Шаг 4: Валидация данных

ProcessingTable автоматически выполняет валидацию на основе правил из `TabTableSchema`:

- Проверка типов данных (int, float, text)
- Проверка диапазонов значений
- Проверка обязательных полей (NULL VALUE = false)
- Проверка уникальности (UNIQUE FLAG = true)

При обнаружении ошибок в результирующей таблице появится колонка `ValidationErrors` с описанием проблем.
